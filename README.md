# Pollinations for MIT App Inventor and Kodular

[![Made with pollinations.ai](https://raw.githubusercontent.com/pollinations/pollinations/main/packages/ui/src/brand/badge-made-with.svg)](https://pollinations.ai/?ref=badge)

One extension that gives an app text, images, speech-to-text, questions about a
picture, and a sign-in so **no API key ships inside the app** — the user connects
their own Pollinations account and pays with their own Pollen.

![The blocks and an image the extension fetched](docs/screenshot.png)

Built for the Pollinations quests
[#17247](https://github.com/pollinations/pollinations/issues/17247) (App Inventor) and
[#17248](https://github.com/pollinations/pollinations/issues/17248) (Kodular).

## Blocks

| Block                                | What it does                                                                                               |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `Ask(prompt)`                        | Asks the text model. Raises `GotText`                                                                      |
| `GenerateImageUrl(prompt)`           | Renders an image. Raises `GotImageUrl` with a link                                                         |
| `DownloadImage(prompt, fileName)`    | Renders an image into the app's files. Raises `GotImageFile` with the path, ready for an `Image` component |
| `TranscribeRecording(filePath)`      | Sends a recording (for example from `SoundRecorder`) to speech-to-text. Raises `GotText`                   |
| `AskAboutImage(imagePath, question)` | Asks the text model about a picture from the `Camera`, `ImagePicker` or a file. Raises `GotText`           |
| `ListModels(imageModels)`            | Lists the live model ids. Raises `GotModels`                                                               |
| `StartSignIn()`                      | Starts the device-flow sign-in. Raises `GotSignInCode`, then `SignedIn`                                    |

Events: `GotText`, `GotImageUrl`, `GotImageFile`, `GotModels`, `GotSignInCode`,
`SignedIn`, `GotError`.

Properties: `ApiKey`, `TextModel`, `ImageModel`, `ImageSize`, `SystemPrompt`.

`TranscribeRecording` and `AskAboutImage` are the two things the `Web` component handles
badly: the first needs a multipart upload of a file, the second needs a picture inline in
the request. Both are one block here.

## How it works

Every call lives in `src/dev/pollinations/ai2/PollinationsApi.java`:

| What | Call | Code |
| --- | --- | --- |
| Text, and questions about a picture | `POST https://gen.pollinations.ai/v1/chat/completions` | `PollinationsApi.java:99`, `:240` |
| Image as a URL | `POST https://gen.pollinations.ai/v1/images/generations` with `response_format: "url"` | `PollinationsApi.java:121` |
| Image as a file | `GET https://gen.pollinations.ai/image/{prompt}?model=…&width=…&height=…` | `PollinationsApi.java:137` |
| Speech to text | `POST https://gen.pollinations.ai/v1/audio/transcriptions`, multipart upload | `PollinationsApi.java:176` |
| Model lists | `GET https://gen.pollinations.ai/text/models`, `GET https://gen.pollinations.ai/image/models` | `PollinationsApi.java:307` |
| Sign-in | `POST https://enter.pollinations.ai/api/device/code`, then `POST https://enter.pollinations.ai/api/device/token` | `PollinationsApi.java:254`, `:274` |

Those two hosts are the constants at `PollinationsApi.java:31` and `:32`. The key travels in the `Authorization: Bearer` header, and
the device flow mints it for the user, so the app ships without one.

## Install

**MIT App Inventor** — open a project, then _Palette → Extension → Import extension_ and
pick `dist/dev.pollinations.ai2.aix`. Drop `Pollinations1` from the extension drawer onto
the screen.

**Kodular** — _Palette → Extensions → Import extension_, same file, then drag
`Pollinations1` onto the screen.

Then either set `ApiKey` in the designer, or call `StartSignIn` so the user approves their
own account:

```
when Button1.Click
    call Pollinations1.StartSignIn

when Pollinations1.GotSignInCode (code, url)
    set Label1.Text to join "Open " url " and enter " code

when Pollinations1.SignedIn
    set Label1.Text to "Ready"
```

`ApiKey` is then filled in for you. Nothing has to be typed or shipped in the APK.

## The sample project

`sample/sample-PollinationsComic.aia` is a small app that already contains the extension
and five blocks:

- `Button1.Click` → `Pollinations1.Ask(TextBox1.Text)`
- `Button2.Click` → `Pollinations1.DownloadImage(TextBox1.Text, "comic.png")`
- `Pollinations1.GotText` → `Label1.Text`
- `Pollinations1.GotImageFile` → `Image1.Picture`
- `Pollinations1.GotError` → `Label1.Text`

Be aware of how it was made, because it matters if something looks off: the project was
generated by `tools/make_sample.py`, which follows the layout of MIT App Inventor's own
extension test fixture and takes every version number from App Inventor's
`YaVersion.java` (`YaVersion 237`, `Form 32`, `Button 8`, `TextBox 15`, `Label 6`,
`Image 8`). Its structure, JSON and block XML were checked offline. **It has not been
imported in App Inventor or Kodular**, because that needs the web editors. If it refuses
to import, the extension is unaffected — build the same five blocks by hand in a minute.

## Build from source

```bash
./build.sh                 # pulls the official template and its jars, then runs ant
```

The build uses MIT App Inventor's own toolchain, so the `.aix` is produced exactly the way
the platform expects:

- `extension-template` for `build.xml`, which jacks the sources, dexes them into
  `classes.jar`, and zips the `.aix`
- `extension-deps` for `AndroidRuntime.jar`, `annotation.jar`, `android.jar` and the
  annotation processor that turns the annotations into `component.json`

Nothing of theirs is vendored in this repository.

## Tests

```bash
# the API layer, against a local stub server: no key, no network, no device
curl -LO https://repo1.maven.org/maven2/org/junit/platform/junit-platform-console-standalone/1.11.3/junit-platform-console-standalone-1.11.3.jar
javac -cp junit.jar:lib/appinventor/gson-2.1.jar -d build/test \
      src/dev/pollinations/ai2/PollinationsApi.java test/dev/pollinations/ai2/PollinationsApiTest.java
java -jar junit.jar execute -cp build/test:junit.jar --select-class dev.pollinations.ai2.PollinationsApiTest
```

16 tests cover the request building, the auth header, the image-size clamping, the
multipart upload, the inline-image request, the whole device flow (pending, approved,
denied), the error messages and the base64 encoder.

## What is and is not verified

Verified here:

- **16/16 unit tests** of the API layer against a stub HTTP server
- **Live calls** with the same class: `ask` answered, 217 text and 87 image models listed,
  an image URL returned, a 512x512 image written to disk, a device code issued and polled
- **The `.aix`** is built by App Inventor's own template; the annotation processor reports
  7 methods, 7 events and 5 properties, and `component_build_info.json` carries
  `android.permission.INTERNET`
- **The sample's structure**: zip layout, designer JSON, block XML and component versions

Not verified: importing the `.aix` or the sample into the App Inventor or Kodular web
editors and running it on a device. That is not possible from a build machine, and the
quest warns that some App Inventor extensions break in Kodular. Please try the sample
first; if Kodular refuses it, that is what to fix.

## Two details worth knowing

- The image endpoint requires **at least 256 px per side**; smaller requests are refused
  with `400`. `ImageSize` is clamped, so 8 becomes 256 and the image still works.
- App Inventor bundles **Gson 2.1**, so the parsing uses that API
  (`new JsonParser().parse(...)`), not the newer static call. The extension source also
  stays at **source level 7**, which is what the template compiles with.
